# FinTrack — учёт личных финансов на Blazor

FinTrack — кроссплатформенное веб-приложение на **C# / .NET 10 / Blazor**. В нём можно вести счета, доходы и расходы, ставить месячные бюджеты, смотреть аналитику и импортировать банковские выписки из CSV. Категория операции подбирается автоматически моделью **ML.NET**.

## Возможности.

- **Счета**: Kaspi, наличные и т. д., баланс считается автоматически.
- **Категории** с цветами, иконками и ключевыми словами.
- **Операции**: добавление, редактирование, удаление, поиск, фильтры по периоду, счёту и категории; виртуализированная таблица.
- **Бюджеты**: месячные лимиты по категориям, предупреждение на 80% и 100%, копирование из прошлого месяца.
- **Обзор**: баланс, доходы и расходы за месяц, прогноз трат к концу месяца, круговая диаграмма по категориям, график за 6 месяцев.
- **Импорт CSV**: автоопределение разделителя, русские и английские заголовки, предпросмотр, поиск дубликатов, ошибки по строкам.
- **ML.NET**: многоклассовая классификация текста (FeaturizeText + SdcaMaximumEntropy). Модель обучается на ваших операциях и дообучается после импорта. Если она не уверена, категория подбирается по ключевым словам.
- **SignalR**: уведомления о превышении бюджета; данные обновляются сразу во всех открытых вкладках и на всех устройствах.
- **Адаптивный интерфейс**: MudBlazor, тёмная тема, боковое меню на ПК и нижнее меню на телефоне.

## Запуск

Нужен **.NET 10 SDK** (https://dotnet.microsoft.com/download).

```bash
cd src/FinTrack.Web
dotnet run
```

Откройте http://localhost:5080. База `fintrack.db` создаётся сама и заполняется демо-данными за 3 месяца.

**Чтобы открыть с телефона** (компьютер и телефон в одной Wi-Fi сети):

```bash
dotnet run --launch-profile "lan (для телефона)"
```

Затем на телефоне откройте `http://<IP компьютера>:5080`. IP можно узнать командой `ipconfig` (Windows) или `ifconfig` (macOS/Linux). Если не открывается, разрешите порт 5080 в брандмауэре.

**Сбросить демо-данные:** остановите приложение и удалите `src/FinTrack.Web/fintrack.db`.


## Тесты

```bash
dotnet test
dotnet test --collect:"XPlat Code Coverage"   # с покрытием
```

- **Unit** (xUnit): форматирование и разбор сумм, прогноз, статусы бюджета, валидация, разбор CSV, ключевые слова.
- **Интеграционные**: сервисы на настоящей SQLite в памяти — баланс, уведомление о превышении бюджета, запрет удаления категории, копирование бюджетов, импорт с дубликатами, обучение ML-модели.
- **Компонентные** (bUnit): `MoneyText`, `BudgetProgress`, обобщённый `EntityGrid<TItem>`.

## Архитектура

```
src/FinTrack.Web/
├── Domain/        сущности: Account, Category, Transaction, Budget
├── Data/          AppDbContext (EF Core + SQLite), SeedData
├── Services/      бизнес-логика за интерфейсами: счета, категории, операции,
│                  бюджеты, статистика, CSV-импорт, ML.NET, AppState
├── Hubs/          SignalR-хаб и сервис уведомлений
└── Components/
    ├── Layout/    MainLayout (тема, SignalR-клиент, ErrorBoundary), меню
    ├── Pages/     Обзор, Операции, Бюджеты, Счета, Категории, Импорт
    ├── Shared/    переиспользуемые компоненты: MoneyText, StatCard, BudgetProgress,
    │              TransactionList, MonthSelector, EmptyState, EntityGrid<TItem>
    └── Dialogs/   формы: операция, счёт, категория, лимит
tests/FinTrack.Tests/   xUnit + bUnit
```

**Поток данных:** страница → интерфейс сервиса (DI) → `IDbContextFactory<AppDbContext>` → SQLite. После изменения данных сервис через `INotificationService` (SignalR) рассылает событие `DataChanged`. `MainLayout` принимает его и вызывает `AppState.NotifyDataChanged()`, а страницы, подписанные на `AppState.OnChange`, перезагружают данные.

**Ключевые решения:**

- **SOLID.** Страницы зависят только от интерфейсов (`ITransactionService` и т. д.). Реализации регистрируются в `Program.cs`, поэтому в тестах их легко подменить (`FakeNotifications`).
- **`IDbContextFactory`.** В Blazor Server компонент живёт долго, а `DbContext` не потокобезопасен. Поэтому на каждую операцию создаётся новый короткоживущий контекст.
- **`decimal` для денег**, а не `double`, — чтобы не было ошибок округления.
- **Ошибки:** сервисы возвращают `Result` с понятным текстом вместо исключений. `ErrorBoundary` ловит сбои компонентов. Если SignalR недоступен, приложение продолжает работать без живых уведомлений. Если ML-модель не обучилась, подбор идёт по ключевым словам.
- **Производительность:** `AsNoTracking` для чтения, индекс по дате, `Virtualize` в таблицах, обучение модели в фоне.
- **Компоненты:** `[Parameter]`, `EventCallback<T>`, templated-компонент `EntityGrid<TItem>` с `RenderFragment<TItem>`, состояние через scoped-сервис `AppState`, `CascadingParameter` в диалогах.

## Формат CSV для импорта

```csv
Дата;Описание;Сумма
01.11.2026;Magnum Cash&Carry;-14 250,00
05.11.2026;Зарплата;280 000
```

Расходы указываются с минусом. Даты: `dd.MM.yyyy`, `yyyy-MM-dd`, `dd/MM/yyyy`. Пример файла есть на странице импорта.

## Планы развития

- Вход и роли через ASP.NET Core Identity (многопользовательский режим).
- .NET MAUI Blazor Hybrid — нативное приложение для Windows, macOS, Android и iOS на тех же компонентах.
- Офлайн-режим (PWA + IndexedDB) с синхронизацией.
- PostgreSQL + Docker, CI в GitHub Actions, E2E-тесты на Playwright.
- Экспорт отчётов в PDF, казахский язык интерфейса.
